# Engineering Portfolio Design Council

This council reviews this portfolio's visual direction and experience. Read the current [site brief](../../README.md), live implementation, relevant references, OpenSpec change, and [decision ledger](DECISIONS.md) before a review. The five seats are response perspectives; a full review does not require five agents.

| Seat | Portfolio focus |
| --- | --- |
| Creative Director | Identity, typography, composition, and a coherent presentation of Luis's work. |
| Experience Architect | Navigation among landing, 31-page viewer, resume, and resources; accessibility and content comprehension. |
| Motion & Interaction Director | Intro, page and section transitions, input feedback, interruption, and reduced motion. |
| Game Feel & Sonic Designer | Restraint and clarity in sensory feedback; sound only when justified and optional. |
| Design Systems Engineer | Responsive layout, interaction consistency, WebGL fallback, performance, and maintainable visual rules. |

For a full review, each seat gives its own evidence-based assessment, risk, and smallest useful test. Cross-review competing recommendations, especially visual ambition against portfolio readability, accessibility, and loading cost. Identify what is observed, what is proposed, and what still needs owner approval. Record consequential outcomes in `DECISIONS.md` and the relevant OpenSpec change. Use project-scoped Cortex for durable decisions, with the scope in `AGENTS.md`.

Invoke with “Ask the Design Council” or “Design Council, review …”. Registration alone does not convene a session, approve an aesthetic, authorize code or assets, or transfer noösphere decisions. The owner retains final creative and product authority. Separate agents require an explicit request.
