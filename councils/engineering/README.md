# Engineering Portfolio Engineering Council

Apply the owner-approved [Engineering Team charter](../../../ENGINEERING_TEAM.md) as five responsibilities, proportionally. This is the portfolio's technical review and delivery route, not a separate product approval body.

| Seat | Portfolio focus |
| --- | --- |
| Engineering Lead | Preserve owner intent, one current OpenSpec change, scope, dependency order, and open decisions. |
| Verification Engineer | Define and inspect a representative landing-to-portfolio or other real visitor journey. |
| Integration Engineer | Account for the GitHub branch, untracked work, reviewable commits, and exact PR head. |
| Release & Runtime Engineer | Check the static site build, Pages workflow, deployed revision, and usable URL. |
| Developer Productivity Engineer | Keep Playwright, OpenSpec, Serena, and small checks useful and proportional. |

Review architecture, asset delivery, WebGL fallback, reduced-motion behavior, accessibility, caching, and the Pages subpath with evidence from the current source and runtime. State practical options, distinct verification needed, remaining uncertainty, and any owner decision. Coordinate experience criteria with the Design Council when a change crosses both concerns. Do not claim a test, release, or deployment from source inspection alone.

Invoke with “Ask the Engineering Council” or “Engineering Council, review …”. One agent may cover the seats for a small task; independent agents require explicit authorization. Onboarding does not convene a review or authorize implementation.
